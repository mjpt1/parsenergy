# SolarOps — REST API

Base path: `/api/`  ·  Format: JSON  ·  Interactive docs: **`/api/docs/`** (Swagger UI, generated by drf‑spectacular) · OpenAPI schema: **`/api/schema/`**

## Authentication
Two schemes are accepted:
- **Token** — `Authorization: Token <key>`
- **Session** — Django session cookie (for the web UI)

Obtain a token:
```http
POST /api/auth/login/
Content-Type: application/json

{"username": "alice", "password": "secret"}
→ 200 {"token": "9c2b…"}
```
`POST /api/auth/logout/` revokes the caller's token.

All endpoints require authentication unless noted. Responses are **rate‑limited** (default `60/min` anonymous, `600/min` authenticated; configurable via `THROTTLE_ANON` / `THROTTLE_USER`).

## Conventions
- **Pagination:** page-number, 25/page → `{"count", "next", "previous", "results": [...]}`; use `?page=N`.
- **Filtering:** DjangoFilterBackend on list endpoints.
- **Access scoping:** non‑admin users only see plants they own or are members of (and the data hanging off them).

## Data ingestion (gateways → platform)
```http
POST /api/measurements/upload/
Authorization: Token <gateway-token>
Content-Type: application/json

{
  "plant_code": "PLANT-001",
  "equipment_serial": "INV-001",
  "timestamp": "2026-06-13T09:00:00Z",      // optional
  "measurements": [
    {"parameter": "power",   "value": "321.5", "unit": "kW"},
    {"parameter": "voltage", "value": "690",   "unit": "V"}
  ]
}
→ 201 {"detail": "Created N measurements", "alerts_triggered": K, "measurements": [...]}
```
The plant is scoped to the authenticated token's user. Power/voltage/current/etc. also create a `TelemetryReading` and evaluate alert rules. Real-time updates are pushed over WebSocket `ws/telemetry/` (per‑plant groups).

## Analytics & ML
- `GET /api/plants/{plant_id}/kpi/` → KPIs (`total_power`, `total_energy`, `avg_voltage`, `avg_current`). 404 if the plant isn't in the caller's scope.
- `POST /api/predict/` → ML forecast / fault probability / maintenance recommendation.

## Requests module (customer workflow)
| Endpoint | Purpose |
|---|---|
| `POST /api/request-otp/request/` (public) | Issue SMS OTP (`purpose`: `register`/`login`) |
| `POST /api/request-otp/verify/` (public) | Verify OTP → returns auth `token` |
| `/api/requests/` | Customer requests (scoped); `POST` to submit |
| `POST /api/requests/{id}/select-offer/` | Pick an offer → auto‑generates the contract |
| `GET /api/requests/{id}/contract/` · `POST …/contract/request-otp/` · `POST …/contract/approve/` | Contract view / OTP / approval |
| `GET /api/requests/{id}/messages/` | SMS history for the request |
| `/api/request-offers/` (+ `{id}/toggle/`) | Offers (create/toggle = manager only, max 3/request) |
| `/api/request-contracts/` `/api/request-payments/` | Read‑only, scoped |
| `/api/request-message-logs/` | SMS log (manager only) |

## Localization & calendar
- Language is selected per session/cookie (`POST /i18n/setlang/`, `language=en|fa`); API responses that include human‑readable labels (e.g. status displays) honour the active language.
- Datetimes are stored and returned in **ISO‑8601 (Gregorian, UTC‑aware)**. Calendar conversion to Jalali is a presentation concern handled by the web UI; API consumers convert as needed.

## Errors
Standard HTTP status codes with a JSON body, typically `{"detail": "..."}` or field‑keyed validation errors. Common: `400` validation, `401` unauthenticated, `403` forbidden/permission, `404` not found/out of scope, `429` throttled.
